# 2D 训练数据离线保存（GDINO/DINOv2 等 2D Backbone 特征缓存）

> 目标：把 **在线 2D 特征提取**（例如 GroundingDINO / DINOv2）从训练迭代中移走，提前离线预计算并落盘；训练时只做 **2D→3D 投影采样 / 融合**，从而显著降低训练时间，同时保持 2D‑3D 投影一致性不被破坏。

本文以 AutoSeg3D 中的 GDINO 通路为例（A1/A3），整理一套**对齐安全（alignment‑safe）**的离线缓存方案，并给出可复现的落地步骤与排坑清单。

---

## 1. 为什么要离线缓存？缓存到什么粒度最安全？

### 1.1 在线 GDINO 的开销在哪里
在当前实现里，GDINO 需要在训练循环中反复执行：
- 读图 + resize 到固定尺寸（例如 `(H,W)=(420,560)`）
- 前向提取 `srcs`（image feature pyramid），以及（若启用 DACA‑2D）提取 `hs_last / pred_boxes / pred_scores`

这会显著增加每 iter 的 wall‑time，尤其在 batch_size 大、num_workers 高时更明显。

### 1.2 最推荐的离线缓存（对齐风险最低）
**缓存“纯 2D 输出”，不缓存“投影/融合后结果”。**

推荐缓存两类（按需二选一或同时缓存）：
- **`mode=backbone`**：只缓存 `srcs`（多尺度 feature maps，用于 point‑fusion / sparse‑FPN 注入）
- **`mode=full`**：缓存 `srcs + hs_last + pred_boxes + pred_scores`（同时加速 point‑fusion + DACA‑2D）

为什么这是对齐风险最低的？
- `srcs/hs_last/pred_boxes` 是 **只由图像决定** 的结果；与 3D 增强（flip/rot/scale/elastic）无关。
- 2D‑3D 一致性由 **投影几何**保证：`points_raw`（未做 3D 增强的点坐标）+ `cam_info.intrinsics` + `cam_info.pose` + `img_size_gdino`。
- 因此离线缓存只要做到“同一张图片 + 同一套 resize/intrinsics 约定 + 同一套 GDINO 权重”，投影仍然稳定。

### 1.3 不建议离线缓存的内容（容易破坏一致性）
以下缓存会显著增加对齐风险（除非你额外实现严格的坐标变换链路）：
- **每点 2D 特征（N×256）**：点顺序/采样数变化会导致错位；文件体积也更大。
- **DACA‑2D 的 `query2d_pos`（lift 到 3D 的 anchor）**：当前实现中 anchor 依赖 `xyz_aug`（做过 `RandomFlip3D + GlobalRotScaleTrans` 的坐标空间）。若离线预计算，必须把 anchor 从 raw 空间变换到 aug 空间，否则训练时会不一致。

> 结论：建议把离线缓存边界放在 “GDINO 输出” 这一层；投影采样/融合仍在线做。

## 2. AutoSeg3D 当前对齐约定（必须理解清楚）

以 SV（单帧）配置为例：
- `AutoSeg3D/configs/scannet200/AutoSeg3D_sv_scannet200_A1_2dca.py`
- `AutoSeg3D/configs/scannet200/AutoSeg3D_sv_scannet200_A3_fpn_2dca_autoloss.py`

### 2.1 数据 pipeline 中与投影相关的关键步骤
典型顺序（SV）：
1) `PrepareSVForOnline(apply_axis_align=False)`  
   - 关键点：SV 的 pose/infos 与点云已经在同一约定下，**强行 axis_align 可能导致大量帧 valid_ratio 掉到 0**。
2) `BuildCamInfoFromPoses(dataset_type='scannet200')`  
   - 产出 `cam_info`（含 `intrinsics`, `pose/extrinsics` 等）。
3) `ResizeForGDINO(target_size=(420,560))`  
   - 注意：这里主要是**更新** `cam_info[*].intrinsics` 与 `cam_info[*].img_size_gdino`。
4) `NormalizeCamInfo(strict=True)`  
   - 统一结构，避免 collate 后出现嵌套 list 导致投影读字段混乱。
5) `SavePointsForProjection`  
   - 缓存 `points_raw`（3D 增强前的点）用于后续投影。

### 2.2 模型端投影采样时使用的坐标空间
以 `AutoSeg3D/oneformer3d/mixformer3d.py` 为准：
- **point‑fusion**：优先使用 `points_raw` 做投影（保证与 pose/intr 对齐），采样出的 per‑point 2D feature 再回写到对应点索引上。
- **DACA‑2D**：2D box support points 的 3D 聚合（median/voxel downsample 等）在实现里通常用 `xyz_aug`（增强后的空间，用于 decoder 内距离门控/attention mask）。

> 这意味着：离线缓存 `srcs/hs_last/pred_boxes` 是安全的；离线缓存 “已经 lift 到 3D 的 anchor” 需要额外把 raw→aug 变换链路固定下来。

### 2.3 半像素对齐（容易踩坑）
在图像坐标到 feature map 坐标缩放时，当前实现使用 `align_corners=False` 的半像素规则：
- `AutoSeg3D/oneformer3d/projection_utils.py:scale_uv_img_to_feat()`

离线缓存只存 2D 输出时，这部分逻辑仍在线执行，所以只需要保证：
- `ResizeForGDINO` 更新 intrinsics 的规则不变（纯 scale）
- `img_size_gdino` 与实际 GDINO 输入一致

## 3. “多尺度 srcs 为何要存下来？能不能只存最高分辨率？”

对于 GDINO 来说，多尺度 `srcs` 是来自不同 backbone feature level（不同 stride / 不同语义层级）的输出，不是“最高分辨率那张图简单下采样就能等价重建”的。

因此：
- 若你配置 `feat_levels=[0,1,2,3]`（A3 默认），要保持方法等价，**就应缓存这几层 `srcs`**。
- 如果你只想存一层（减小磁盘/计算），可以做一个严格消融：把 `feat_levels` 改成单层（例如 `[0]`），并只预计算 `mode=backbone`。这会改变方法本身，结果不能与多层设置直接等价对比。

## 4. 离线缓存设计（推荐实现）

### 4.1 cache key：必须包含哪些字段
离线缓存必须与如下条件强绑定，否则会出现“命中但不一致”的隐蔽错误：
- 绝对 `img_path`
- `target_hw`（即 `img_size_gdino`，例如 420×560）
- GDINO 模型配置与权重（repo_dir / config_path / checkpoint）
- caption（对 full forward 的 text encoder 有影响）
- mode（`backbone` vs `full`）

### 4.2 存储内容与 dtype
推荐：
- 以 **per‑image** 为单位存 `.pt`：
  - `backbone`：`srcs: List[Tensor(C,H,W)]`
  - `full`：额外存 `hs_last, pred_boxes, pred_scores`
- dtype：
  - `srcs` 建议 `fp16`（体积减半；对 point‑fusion 影响一般很小）
  - `hs_last/pred_boxes/pred_scores` 若担心阈值边界影响，可用 `fp32`（但体积更大）

### 4.3 目录结构（建议）
按 mode 分开，避免混用：
```
<cache_dir>/
  backbone/<shard>/<shard>/<hash>.pt
  full/<shard>/<shard>/<hash>.pt
```

## 5. AutoSeg3D 已落地的缓存实现（代码位置）

本仓库已实现一套最小可用的 GDINO cache（以 “纯 2D 输出” 为缓存边界）：
- `AutoSeg3D/oneformer3d/gdino_cache.py`：cache key / load / save（支持 batched & single）
- `AutoSeg3D/oneformer3d/mixformer3d.py`：
  - SV：`ScanNet200MixFormer3D` 的 point‑fusion / DACA‑2D 读取缓存
  - Online：`ScanNet200MixFormer3D_Online` 的 point‑fusion / DACA‑2D 读取缓存
  - point‑fusion 支持优先读 `full`，miss 时再读 `backbone`
- `AutoSeg3D/tools/precompute_gdino_cache.py`：离线预计算脚本（从 config 解析 dataset/ann_file/img_path）

训练时启用缓存的方式（二选一）：
1) 环境变量（推荐，侵入最小）：
   - `export GDINO_CACHE_DIR=/path/to/gdino_cache`
2) 在 config 的 `gdino_point_fusion` / `gdino_daca2d` 中加入：
   - `cache_dir='/path/to/gdino_cache'`

## 6. 离线预计算：推荐流程（SV / MV 通用）

### 6.1 选择正确的 Python 环境
注意：预计算必须运行在“训练同环境”（能 import torch/mmengine/mmdet3d/oneformer3d/GroundingDINO）。

例如你日志里训练环境是 Python 3.8 + torch 1.13.1（ESAM env），则：
- 用 `/home/nebula/miniconda3/envs/ESAM/bin/python`

### 6.2 只为 point‑fusion 预计算（最快）
只缓存 `srcs`（backbone_only），适合 A3 主要瓶颈在 point‑fusion 的情况：
```bash
/home/nebula/miniconda3/envs/ESAM/bin/python AutoSeg3D/tools/precompute_gdino_cache.py \
  AutoSeg3D/configs/scannet200/AutoSeg3D_sv_scannet200_A3_fpn_2dca_autoloss.py \
  --split train \
  --cache-dir /path/to/gdino_cache \
  --mode backbone \
  --dtype fp16 \
  --batch-size 1
```

### 6.3 同时为 DACA‑2D 预计算（更全）
需要 `hs_last/pred_boxes/pred_scores` 时用：
```bash
/home/nebula/miniconda3/envs/ESAM/bin/python AutoSeg3D/tools/precompute_gdino_cache.py \
  <your_config.py> \
  --split train \
  --cache-dir /path/to/gdino_cache \
  --mode full \
  --dtype fp16 \
  --batch-size 1
```

> 说明：full forward 会走 tokenizer/text encoder，速度比 backbone_only 慢很多；但训练时会省更多 iter 时间。

### 6.4 预计算 val/test（可选但推荐）
如果验证/测试也启用 GDINO（比如 DACA‑2D 评估/诊断），建议也预计算：
```bash
... precompute_gdino_cache.py <config.py> --split val  --cache-dir ... --mode backbone
... precompute_gdino_cache.py <config.py> --split test --cache-dir ... --mode backbone
```

## 7. 训练时如何确认“缓存生效且对齐没坏”

### 7.1 确认 cache hit
最直接的方式：
- 训练时设置 `GDINO_CACHE_DIR`，并观察 GPU 利用率/iter time 是否下降明显。
- 若需要更硬核的确认，可在 `mixformer3d.py` 加一条低频日志（例如每 N iter 打印一次 “cache hit/miss”），但建议不要默认打开以免影响速度。

### 7.2 确认投影一致性（最关键）
对齐是否坏了，首要指标不是 loss，而是 **valid_ratio**（投影后落在 feature map 内且深度有效的点比例）：
- point‑fusion：`[GDINO][point_fusion][valid_ratio] ...`
- DACA‑2D：`[GDINO][daca2d][valid_ratio] ...`

经验建议：
- 在 subset（几十个 scene）上先跑 `strict=True`，确保 `valid_ratio_mean` 稳定接近 1（或至少达到你设定的阈值，例如 0.95）。
- 缓存启用前后，valid_ratio 的统计应一致（差异很小）。若差异很大，优先排查 `img_size_gdino/intrinsics/pose`。

## 8. 常见坑与排查清单（务必逐条核对）

1) **`ResizeForGDINO` 只更新了 intrinsics，但你实际 GDINO 输入尺寸不一致**  
   - 训练端代码会 `Image.open(...).resize((w,h))`，要求与 `cam_info.img_size_gdino` 完全一致。
2) **`apply_axis_align` 用错**（SV 特别常见）  
   - SV 推荐 `PrepareSVForOnline(apply_axis_align=False)`；否则 pose 与点云不在同一空间。
3) **没带 `SavePointsForProjection`，导致投影用的是增强后的点**  
   - 会破坏 2D‑3D 对齐（尤其随机旋转/缩放时）。
4) **cache key 没包含 checkpoint/config/caption**  
   - 轻则 silent mismatch，重则训练完全不收敛但你以为“缓存正确”。
5) **多卡/多进程并发写 cache**  
   - 建议预计算阶段单进程写；或让不同 rank 写不同 split/shard（否则可能出现部分写入/文件损坏）。
6) **图像路径在不同机器/挂载点变化**  
   - 由于 key 含绝对路径，换机器可能导致全 miss。解决：统一 data_root 挂载路径，或改 key 使用相对路径（但要非常小心避免冲突）。

## 9. 扩展：想更像 DITR 的“3D 端构造多尺度”怎么做？

如果目标是贴近 DITR（DINO in the Room）的思路：2D 端只给每点一个向量，多尺度完全靠 3D pooling：
- 把 GDINO 的 `feat_levels` 改为单层（例如 `[0]`），甚至直接用 DINOv2 patch embedding 做单尺度点特征；
- 之后用 `build_sparse_fpn()` 或 encoder 内的 downsample 自然形成层级；
- 在 decoder skip 注入层层相加（或类似 A3 的 sparse‑FPN injection）。

这类改动属于“方法消融”，不再等价于当前 A3 的多层 GDINO 设定，优点是更简单、更省缓存空间；缺点是可能损失多尺度语义。

## 10. 指令汇总：离线预计算 + 训练（Object / Cluster20）

本节把“离线提取 2D 特征（GDINO cache）”与“启用 cache 训练”的常用指令整理成可直接复制的版本。

### 10.1 预计算（推荐：只跑 MV，一次覆盖 SV）

**核心原因**：SV 与 MV 的差异主要是 **同一 scene 的采样频率**；两者都从第 0 帧开始采样，因此 **MV 的图像集合是 SV 的超集**。  
因此：只要你把 MV 的图像全部 cache 好，SV 训练/测试会天然命中其中的子集，不需要再单独跑一遍 SV（除非你只拥有 SV 的 infos pkl 或只想做极小规模验证）。

下面所有命令都采用同一“规范根”（你提出的做法）：
- `--data-root /home/nebula/xxy/dataset`（让 `2D/...` 相对路径拼出的绝对路径稳定）
- `--ann-file` 传 **绝对路径**（避免 config 中 symlink/相对路径差异导致 cache miss）

> 备注（4090）：`mode=full` 的显存占用更高，建议从 `--batch-size 1` 开始，稳定后再尝试 `2~4`；`mode=backbone` 往往可以更大（例如 `8~16`），以 OOM 为准。

#### 10.1.1 Object（caption='object.'）— 推荐 full（同时加速 point-fusion + DACA-2D）

```bash
PY=/home/nebula/miniconda3/envs/ESAM/bin/python
DATA_ROOT=/home/nebula/xxy/dataset
CACHE_DIR=/home/nebula/xxy/dataset/gdino/scannet200_gdino_full_object

# MV train
$PY AutoSeg3D/tools/precompute_gdino_cache.py \

  --split train \
  --data-root $DATA_ROOT \
  --ann-file $DATA_ROOT/data/scannet200-mv_fast/scannet200_mv_oneformer3d_infos_train.pkl \
  --cache-dir $CACHE_DIR \
  --mode full \
  --dtype fp16 \
  --batch-size 1

# MV val（建议也做，避免 val/test 仍在线跑 GDINO）
$PY AutoSeg3D/tools/precompute_gdino_cache.py \
  AutoSeg3D/configs/scannet200/AutoSeg3D_scannet200_stage1_A3_fpn_2dca_autoloss_cat.py \
  --split val \
  --data-root $DATA_ROOT \
  --ann-file $DATA_ROOT/data/scannet200-mv_fast/scannet200_mv_oneformer3d_infos_val.pkl \
  --cache-dir $CACHE_DIR \
  --mode full \
  --dtype fp16 \
  --batch-size 1
```

> 如果你只想加速 point‑fusion（不需要离线 DACA‑2D），把 `--mode full` 改成 `--mode backbone` 即可（同一 `CACHE_DIR` 下会写到 `backbone/` 子目录）。
